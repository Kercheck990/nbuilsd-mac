# NFT-GRADER

Кроссплатформенное приложение-апгрейдер NFT-подарков: Flutter-клиент
(Android / iOS / Windows) + бэкенд на Node.js и PostgreSQL.

```
├── lib/                  Flutter-клиент
├── assets/gifts/         ← сюда кладёте картинки своих подарков
├── server/               Node.js + PostgreSQL (аккаунты, платежи, топы)
└── pubspec.yaml
```

---

## 1. Как заполняется шкала

Дуга заливается **ровно по проценту**: 50% шанса — ровно половина сектора,
75% — три четверти. Сектор 75–100% нарисован красной штриховкой: это
запретная зона.

**Потолок — 75%.** Если ставка относительно цели даёт больше, кнопка
апгрейда блокируется, шкала краснеет, под ней появляется подсказка
«уменьшите ставку или выберите цель дороже». Быстрые пресеты (`x2`, `50%`)
тоже не могут выбрать цель за потолком.

Значение задано **в одном месте** на каждой стороне:

| Где | Файл |
|---|---|
| Клиент | `lib/core/constants/app_constants.dart` → `maxChancePercent` |
| Сервер | `server/src/config.js` → `game.maxChancePercent` |

Оба должны совпадать. Сервер проверяет потолок независимо — раунд с
шансом выше 75% отклоняется, даже если запрос пришёл в обход приложения.

Во время прокрутки по шкале бежит жёлтая точка и останавливается на
позиции реального ролла с сервера. Попала внутрь залитой части — победа.

## 2. Свои подарки

1. Положите картинку в `assets/gifts/` — например `nft_016.png`
   (квадрат 512×512, прозрачный фон).
2. Добавьте строку в `lib/data/gifts/gift_assets.dart`:

   ```dart
   'nft_016': 'nft_016.png',
   ```

3. Заведите сам предмет — в `lib/data/mock/mock_data.dart` (офлайн-режим)
   или в `server/db/seed.sql` (таблица `items`).

Папка подключена в `pubspec.yaml` целиком. Нет файла — карточка покажет 🎁
и не упадёт.

## 3. Языки

Русский, украинский, английский. Словари — `lib/core/l10n/app_localizations.dart`,
переключение в настройках применяется мгновенно и сохраняется. При первом
запуске берётся язык системы, если поддерживается, иначе русский.

Новая строка: добавьте ключ во **все три** карты (`_ru`, `_uk`, `_en`) и
используйте `context.l10n.t('ключ')` или `context.l10n.f('ключ', {'name': '…'})`.

## 4. Регистрация и код на почту

Экраны: `/login`, `/register`, `/verify`.

Поток: регистрация → сервер создаёт неподтверждённый аккаунт и шлёт
6-значный код → ввод кода → выдаётся JWT. До подтверждения токен не
выдаётся. Код живёт 10 минут, хранится только его SHA-256, максимум
5 попыток, повторная отправка раз в 60 секунд.

Анимации: дрейфующие цветные пятна и мерцающие частицы на фоне,
стеклянные карточки с блюром, поочерёдный выезд полей, пульсирующий
логотип, тряска при ошибке, отдельные ячейки для кода.

---

## 5. Инвентарь и топы

**Инвентарь** (`/inventory`): суммарная стоимость, сортировка, фильтр по
редкости, продажа предмета за монеты.

**Топы** (`/leaderboard`): метрики — по стоимости инвентаря, по победам,
по профиту; периоды — день, неделя, всё время. Пьедестал для первой
тройки, своя строка подсвечена.

## 6. Пополнение

Настоящее, через провайдеров: Stripe (карты), Crypto Pay/@CryptoBot
(USDT, TON), Telegram Stars.

Монеты начисляются **только** в обработчике вебхука после проверки
подписи. Клиент баланс не трогает, повторный вебхук ничего не задвоит.
Ключи и настройка — `server/README.md`.

## 7. Запуск

### Сервер

```bash
cd server
cp .env.example .env     # DATABASE_URL, JWT_SECRET, SMTP, ключи платежей
npm install
npm run seed             # таблицы + каталог
npm run dev
```

База — PostgreSQL на **Supabase**. Создайте проект на supabase.com, возьмите
строку подключения (Settings → Database → Connection string → **Session
pooler**, порт 5432) и подставьте в `DATABASE_URL` при `DATABASE_SSL=true`.
Сервер сам создаст таблицы командой `npm run seed`. Подробности и почему
именно Session pooler — в `server/README.md`.

Для локальной разработки без Supabase подойдёт обычный Postgres в Docker:

```bash
docker run -d --name nft-pg -p 5432:5432 \
  -e POSTGRES_USER=nft -e POSTGRES_PASSWORD=nft -e POSTGRES_DB=nft_grader \
  postgres:16
```

### Клиент

```bash
flutter pub get
flutter run --dart-define=API_BASE_URL=http://10.0.2.2:8080   # Android-эмулятор
flutter run -d windows --dart-define=API_BASE_URL=http://localhost:8080
```

Платформы, если ещё не созданы:

```bash
flutter create --platforms=android,ios,windows .
```

## 8. Честность раундов

Перед броском сервер генерирует `server_seed` и публикует его SHA-256,
после раунда раскрывает сам сид. Игрок пересчитывает результат сам:

```
roll = (первые 13 hex sha256("serverSeed:clientSeed:nonce") / f×13) × 100
победа, если roll < chance
```

Все поля сохраняются в таблице `rounds` и отдаются через `/api/history`.

Клиентский `MockUpgradeApi` в `lib/services/rng_service.dart` остаётся для
работы без сервера — в продакшене раунды ведёт только сервер
(`POST /api/upgrade`).

## 9. Юридическое

Механика «поставил ценность → можешь её потерять» с пополнением реальными
деньгами в большинстве юрисдикций (включая Украину) регулируется как
азартная игра: нужна лицензия, верификация возраста и личности,
ограничения по рекламе. App Store и Google Play такие приложения ревьюят
отдельно, а в ряде стран они запрещены.

Галочка 18+ при регистрации и раздел «Ответственная игра» — минимум, а не
комплаенс. Проконсультируйтесь с юристом по игорному праву в каждой
целевой стране до подключения боевых платёжных ключей и публикации.
